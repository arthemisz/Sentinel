# Security Policy

## Supported versions

Security fixes are generally made against the latest version on the `master` branch. Older releases may not receive a backport.

## Reporting a vulnerability

Please do not report security vulnerabilities in a public issue or pull request.

Use GitHub's private vulnerability reporting feature on the Sentinel repository to send a report to the maintainers. Include:

- A clear description of the vulnerability and its impact.
- The affected component, version, commit, or configuration.
- Reproduction steps or a minimal proof of concept.
- Any suggested mitigation, if known.

You may redact sensitive details until the maintainers can confirm a private channel. Reports are reviewed as soon as practical. Please allow time for investigation before publicly disclosing the issue.

## Scope

Reports involving the web application, CLI, Rust analysis engine, authentication, dependencies, or handling of scanned source code are in scope when they create a security risk for Sentinel users or their data.

For ordinary bugs, feature requests, or questions, use the appropriate public issue template instead.
